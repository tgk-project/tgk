# Requirements Document

## Introduction

TGKプロジェクトでは、キーボードの設定ファイル（keyboard.json）で指定されたキースキャンタイプに基づいて、適切なキースキャンマトリックスの実装を動的に読み込む機能が必要です。現在の実装では、型の不一致やインターフェースの互換性の問題があり、これらを解決する必要があります。また、設定の柔軟性を向上させ、新しいキースキャンタイプの追加を容易にする拡張性も求められています。

## Requirements

### Requirement 1

**User Story:** キーボード開発者として、keyboard.jsonファイルでキースキャンタイプを指定し、それに応じた適切な実装が自動的に選択されるようにしたい。これにより、異なるキーボードハードウェアに対して同じファームウェアを使用できるようになります。

#### Acceptance Criteria

1. WHEN keyboard.jsonファイルでkeyscanフィールドが指定されている場合 THEN システムはその値に基づいて適切なキースキャンマトリックスの実装を選択すること
2. WHEN keyscanフィールドが指定されていない場合 THEN システムはデフォルトのキースキャンマトリックス（MX）を使用すること
3. WHEN 未知のキースキャンタイプが指定された場合 THEN システムは適切なエラーメッセージを表示し、デフォルトの実装を使用するか初期化を中止すること

### Requirement 2

**User Story:** TGKの開発者として、keyscanパッケージとtgkパッケージ間の型の不一致を解消し、クリーンなアーキテクチャを維持したい。これにより、コードの保守性と拡張性が向上します。

#### Acceptance Criteria

1. WHEN keyscan.KeyScanMatrixインターフェースとtgk.KeyScanMatrixインターフェースが使用される場合 THEN 両者の間で型の互換性が保たれること
2. WHEN keyscan.KeyboardConfigとtgk.KeyboardConfigが使用される場合 THEN 両者の間でデータの変換が適切に行われること
3. WHEN 循環参照の問題が発生する可能性がある場合 THEN アダプターパターンなどの適切な設計パターンを使用して問題を回避すること

### Requirement 3

**User Story:** キーボード開発者として、新しいキースキャンタイプを簡単に追加できるようにしたい。これにより、様々なキースイッチ技術に対応したキーボードを開発できるようになります。

#### Acceptance Criteria

1. WHEN 新しいキースキャンタイプを追加する場合 THEN ファクトリー関数の大幅な変更なしに追加できること
2. WHEN 新しいキースキャンタイプが追加された場合 THEN 既存のキースキャンタイプの動作に影響を与えないこと
3. WHEN キースキャンタイプを追加する場合 THEN 共通のインターフェースに準拠するための明確なガイドラインが提供されること

### Requirement 4

**User Story:** キーボード開発者として、キースキャンマトリックスのピン設定などのハードウェア構成をkeyboard.jsonファイルから柔軟に設定できるようにしたい。これにより、コードを変更せずに異なるハードウェア構成に対応できるようになります。

#### Acceptance Criteria

1. WHEN keyboard.jsonファイルでmatrix_pinsが指定されている場合 THEN システムはその設定に基づいてキースキャンマトリックスのピンを設定すること
2. WHEN keyboard.jsonファイルでkeyscan_extra_configsが指定されている場合 THEN システムはその設定に基づいてキースキャンマトリックスの追加設定を行うこと
3. WHEN 設定ファイルに必要な設定が不足している場合 THEN システムは適切なデフォルト値を使用するか、明確なエラーメッセージを表示すること
